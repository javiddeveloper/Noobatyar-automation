# دموی پنل مدیریت نوبت‌یار

اسکرین‌شات‌های این پوشه به‌صورت خودکار تولید می‌شوند. دستی ویرایششان نکنید —
با اجرای دوبارهٔ اسکریپت بازنویسی می‌شوند.

## بازتولید

```bash
cd backend && python seed_demo_data.py
```

سپس با سرور در حال اجرا روی پورت ۸۰۱۰ (فایل‌های استاتیک از همان‌جا خوانده
می‌شوند):

```bash
cd backend && python capture_demo_screens.py
```

`seed_demo_data.py` با یک seed ثابت کار می‌کند، پس دو بار اجرا همان دیتابیس را
می‌سازد و اسکرین‌شات‌ها بعد از هر تغییر استایل قابل بازتولید هستند. پاکسازی
فقط شمارهٔ تلفن‌های `09129…` را هدف می‌گیرد و به سوپریوزر یا دادهٔ تست خودتان
دست نمی‌زند.

## داستان دیتای دمو

هشت کسب‌وکار، هرکدام یک وضعیت مشخص — تا هر حالتی که پنل می‌تواند نمایش دهد
در اسکرین‌شات‌ها دیده شود:

| کسب‌وکار | وضعیت | چه چیزی را نشان می‌دهد |
|---|---|---|
| سالن زیبایی رزانا | تأییدشده، سالم | نمونهٔ اصلی — شش ماه سابقه، صفحهٔ ۳۶۰ پر |
| کلینیک دندانپزشکی مهرگان | تأییدشده، غیبت بالا | کسب‌وکاری که نیاز به پیگیری دارد؛ بیشترین پیامک ناموفق |
| آرایشگاه مردانه آرتا | در انتظار بررسی، ۶ روز | کارت سادهٔ صف بررسی |
| مشاوره تغذیه دکتر نیک‌آیین | در انتظار، نشانه‌گذاری‌شده | کارت صف با کلیدواژه‌های ممنوعه‌ی هایلایت‌شده |
| باشگاه بدنسازی تایتان | تأییدشده، قفل‌شده | قفل مالی ≠ رد محتوایی |
| سالن نگین | معلق | پس از گزارش تخلف، با تاریخچهٔ تصمیم |
| کلینیک زیبایی الماس | رد شده | با دلیلی که برای مالک ارسال شده |
| آرایشگاه سنتی بهار | اشتراک منقضی | تنها ریزش واقعی در بازهٔ گزارش |

عددهایی که در داشبورد می‌بینید از همین وضعیت‌ها ساخته شده‌اند، نه از
`random.choice()`: نرخ ریزش ۳۳٪ حاصل ۲ اشتراک تمدیدنشده از ۶ اشتراک
منقضی‌شده در بازه است، و نرخ شکست پیامک عمدتاً از خط ناپایدار مهرگان می‌آید.

اسکرین‌شات موبایل داخل یک `iframe` با عرض دقیق ۳۹۰ گرفته می‌شود، نه با
`--window-size=390`. دلیلش در کامنت `MOBILE_WIDTH` داخل
`capture_demo_screens.py` توضیح داده شده: کروم هدلس عرض پنجره را حدود ۵۰۰
پیکسل کف می‌گذارد، پس صفحه در ۵۰۰ چیده می‌شد و عکس در ۳۹۰ بریده می‌شد — و روی
صفحهٔ راست‌به‌چپ، بریدگی از ابتدای هر سطر می‌افتاد.

## باز کردن پنل از روی موبایل

سرور با کانفیگ `backend_admin_lan` روی `0.0.0.0:8011` بالا می‌آید (کانفیگ
`backend_admin` روی ۸۰۱۰ دست‌نخورده و فقط لوکال باقی مانده است):

```bash
cd backend && set DEBUG=True&& set ALLOWED_HOSTS=*&& .venv\Scripts\python.exe manage.py runserver 0.0.0.0:8011
```

IP دستگاه خودتان را پیدا کنید:

```bash
powershell -c "Get-NetIPAddress -AddressFamily IPv4 | Where-Object { $_.PrefixOrigin -eq 'Dhcp' } | Select-Object IPAddress, InterfaceAlias"
```

سپس روی گوشی — روی همان شبکه — `http://<آن IP>:8011/admin/` را باز کنید.

`ALLOWED_HOSTS=*` عمداً به‌جای فهرست IP نوشته شده تا آدرس شبکهٔ داخلیِ یک
دستگاه خاص داخل ریپو ثبت نشود و کانفیگ برای بقیه هم کار کند. این کانفیگ فقط
برای توسعه است: `0.0.0.0` یعنی سرور روی کل شبکهٔ محلی در دسترس است، پس
`backend_admin` (پورت ۸۰۱۰، فقط لوکال) به‌عنوان حالت پیش‌فرض دست‌نخورده مانده.

## یک نکته

کارت‌های «سهمیه / کیف‌پول» در صفحهٔ ۳۶۰ کاربر عدد صفر نشان می‌دهند. این ایراد
رابط کاربری نیست: آن ارقام وضعیت لحظه‌ای Redis هستند و در حالت توسعه کش روی
`LocMemCache` است که بین پروسه‌ها مشترک نیست، پس اسکریپت seed نمی‌تواند
مقداردهی‌شان کند. جدول «تاریخچهٔ اعتبار» درست زیر همان کارت‌ها روی دیتابیس است
و پر است — در دمو به آن اشاره کنید. با Redis واقعی کارت‌ها هم پر می‌شوند.
