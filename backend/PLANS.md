# پلن‌ها، قابلیت‌ها و بسته‌های افزودنی نوبت‌یار

سیستم اشتراک نوبت‌یار بر پایه‌ی **نردبان تعهد** کار می‌کند: هر پلن علاوه بر مدت،
یک **بسته‌ی قابلیت** باز می‌کند و هرچه مدت تعهد بلندتر باشد، قابلیت‌ها و سقف‌های
بیشتری در اختیار کاربر قرار می‌گیرد.

این سند مرجع کامل قابلیت‌ها، سقف‌ها، سنجش مصرف، چرخه‌ی عمر اشتراک و بسته‌های
افزودنی است.

---

## ۱. ساختار قابلیت‌ها (Entitlements)

هر پلن یک فیلد `features` (JSON) دارد که مشخص می‌کند چه قابلیت‌هایی باز و چه
سقف‌هایی اعمال شود. کلیدهای رسمی در [`accounting/entitlements.py`](accounting/entitlements.py)
تعریف شده‌اند:

**قابلیت‌ها (بولی):**
| کلید | معنی |
|------|------|
| `online_gateway` | درگاه پرداخت آنلاین (زیبال) |
| `deposit` | دریافت بیعانه |
| `promotional_sms` | پیامک تبلیغاتی/کمپین |
| `capacity_control` | کنترل ظرفیت ساعتی |
| `advanced_reports` | گزارش‌های پیشرفته |
| `multi_channel` | اعلان واتساپ/تلگرام |
| `branded_page` | صفحه‌ی نوبت‌دهی برندشده |
| `priority_support` | پشتیبانی اولویت‌دار |

**سقف‌ها (عدد؛ مقدار `-1` یعنی نامحدود):**
| کلید | معنی |
|------|------|
| `max_businesses` | حداکثر تعداد کسب‌وکار فعال |
| `monthly_appointments` | حداکثر نوبت در ماه |
| `monthly_sms` | اعتبار پیامک ماهانه |

قابلیت‌های مؤثر یک کاربر به این ترتیب حل می‌شوند:

```
پایه (DEFAULT) ← پلن فعال (features) ← بسته‌های افزودنی قابلیتی فعال
```

توابع کلیدی: `entitlements.has_feature(user, key)` و `entitlements.get_quota(user, key)`.
برای گیت‌کردن یک اندپوینت هم می‌توان از permission آماده استفاده کرد:

```python
from accounting.permissions import RequiresFeature
permission_classes = [IsAuthenticated, RequiresFeature('advanced_reports')]
```


## ۳. سنجش مصرف (Usage Metering)

مصرف نوبت و پیامک به‌صورت ماهانه روی Redis شمرده می‌شود
([`accounting/usage.py`](accounting/usage.py)):

- شمارنده‌ی ماهانه: `usage:{user_id}:{metric}:{YYYY-MM}` — ابتدای هر ماه با کلید جدید صفر می‌شود.
- کیف‌پول پیامک: `sms_wallet:{user_id}` — اعتبار دائمیِ خریداری‌شده از بسته‌های افزودنی.

سنجش همیشه بر اساس **صاحب کسب‌وکار** انجام می‌شود (نوبتی که مشتری می‌گیرد از سهمیه‌ی
مالک کم می‌شود). ارسال پیامک ابتدا از سهمیه‌ی ماهانه و پس از اتمام، از کیف‌پول مصرف
می‌شود. اگر Redis در دسترس نباشد، سیستم fail-open است و جریان رزرو متوقف نمی‌شود.

**اعمال سقف‌ها:**
- ساخت کسب‌وکار جدید بیش از `max_businesses` → پاسخ `403`.
- ثبت نوبت پس از پر شدن `monthly_appointments` → پاسخ `409`.
- فعال‌کردن قابلیت‌های گیت‌شده روی کسب‌وکار (درگاه/بیعانه/پیامک تبلیغاتی/کنترل ظرفیت) بدون داشتن قابلیت → پاسخ `403`.
- ارسال پیامک پس از اتمام سهمیه و کیف‌پول → پیامک ارسال نمی‌شود (بدون خطا برای کاربر).

## ۴. چرخه‌ی عمر اشتراک

دستور زیر به‌صورت دوره‌ای (مثلاً کرون ساعتی) اجرا می‌شود:

```bash
python manage.py run_subscription_lifecycle
```

و سه کار انجام می‌دهد:

1. **یادآوری تمدید:** برای اشتراک‌هایی که تا `SUBSCRIPTION_REMINDER_DAYS` روز
   دیگر به پایان می‌رسند، پیامک یادآوری ارسال می‌شود (یک‌بار، با پرچم `reminder_sent`).
2. **انقضا با مهلت گریسفول:** اشتراک‌هایی که بیش از `SUBSCRIPTION_GRACE_DAYS`
   روز از پایانشان گذشته، به وضعیت `expired` می‌روند.
3. **قفل به‌جای حذف:** پس از انقضا، اگر تعداد کسب‌وکارهای کاربر از سقف پلن جدید
   (پایه) بیشتر باشد، کسب‌وکارهای **تازه‌تر قفل می‌شوند** (داده حفظ می‌شود، ولی از
   نوبت‌دهی عمومی حذف و read-only می‌شوند). با تمدید یا ارتقای پلن، از قدیمی‌ترین
   به بعد و تا سقف جدید **باز می‌شوند**.

قفل/بازکردن کسب‌وکارها در [`business/services.py`](business/services.py) (`sync_locks`)
انجام می‌شود و هنگام خرید/تمدید پلن (چه مستقیم، چه از طریق درگاه) به‌صورت خودکار
صدا زده می‌شود. کسب‌وکارهای قفل‌شده از لیست عمومی، جزئیات عمومی و اندپوینت‌های
ساعت خالی حذف می‌شوند و نوبت جدید نمی‌پذیرند.

**متغیرهای محیطی:** `SUBSCRIPTION_REMINDER_DAYS` (پیش‌فرض ۳)، `SUBSCRIPTION_GRACE_DAYS` (پیش‌فرض ۳).

## ۵. بسته‌های افزودنی (Add-ons)

بسته‌ی افزودنی خرید تکی روی هر پلن است، بدون ارتقای کل اشتراک. دو نوع دارد
([`accounting/models.py`](accounting/models.py) → `AddOnPack`):

- **بسته پیامک (`sms_pack`):** `sms_amount` اعتبار پیامک به کیف‌پول کاربر اضافه می‌کند.
- **قابلیت موقت (`feature`):** قابلیت `feature_key` را برای `duration_days` روز فعال می‌کند.

فلوی خرید مشابه اشتراک از طریق زیبال است
([`accounting/payment/addon_payment.py`](accounting/payment/addon_payment.py)) و پس از
پرداخت موفق، benefit مربوطه به‌صورت خودکار اعمال می‌شود. اندپوینت‌ها:

- `GET  /api/accounting/addons/` — لیست بسته‌ها
- `POST /api/accounting/addons/buy/` — خرید (بدنه: `{"pack_id": <id>}`)
- `GET  /api/accounting/addons/payment-result` — callback زیبال

## ۶. نقشه‌ی فایل‌ها

| فایل | نقش |
|------|-----|
| `accounting/entitlements.py` | کلیدهای قابلیت/سقف، بسته‌های پلن، حل قابلیت‌های مؤثر |
| `accounting/usage.py` | شمارنده‌ی ماهانه و کیف‌پول پیامک (Redis) |
| `accounting/permissions.py` | `RequiresFeature` و اعتبارسنجی تنظیمات کسب‌وکار |
| `accounting/payment/addon_payment.py` | پرداخت و فعال‌سازی بسته‌های افزودنی |
| `accounting/management/commands/run_subscription_lifecycle.py` | یادآوری/انقضا/قفل |
| `accounting/management/commands/seed_plans.py` | ساخت پلن‌ها و بسته‌ها |
| `business/services.py` | همگام‌سازی قفل کسب‌وکارها با سقف پلن |
